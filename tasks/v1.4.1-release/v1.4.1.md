# v1.4.1 — Anti-Detection CV Humanization & Multi-Provider LLM Client

## Overview

Two major features delivered together because the second enables the first:

1. **CV Humanization Pipeline** — A multi-pass pipeline that transforms AI-generated CV text into human-sounding text that evades AI detection tools, while preserving all ATS-critical keywords and factual accuracy.

2. **Multi-Provider LLM Client** — Refactor `LLMClient` from a hard-coded Anthropic wrapper into a provider-agnostic abstraction. Adding a new LLM provider (OpenAI, Google Gemini, etc.) should require only a new adapter class and a config entry — no changes to service code.

## Why These Two Together

The humanization pipeline needs to call different models for different passes (Haiku for Pass 1, Sonnet for Pass 3). Currently, `LLMClient` is coupled to `anthropic.AsyncAnthropic` and hardcodes `temperature=0`. Supporting multiple models at different temperatures requires the multi-provider refactor first. Doing both in one release avoids shipping a half-measure where only Anthropic models can be used for humanization.

## Key Design Decisions (confirmed by user)

- **Sonnet 4.6** for the humanization pass (Pass 3), Haiku 4.5 for optimization and keyword audit passes
- **Provider-agnostic LLMClient** — adding a new provider should be a new adapter + config entry, not a service-layer change
- **Temperature=0.3** for humanization pass (not 0) to introduce natural writing variance
- **Algorithmic post-processing** (Pass 5) is cost-free and deterministic — no LLM call
- **CV verification gate** (existing `_verify_customization`) runs after every humanization to catch fabricated claims
- **Configurable models per pass** via `settings.json` — easy to swap to Opus or add OpenAI later
