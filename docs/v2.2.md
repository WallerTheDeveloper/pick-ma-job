# v2.2 Release Notes

**Released:** 2026-04-13
**Branch:** versions/v2.2
**Version file:** `2.2.0`

---

## Shipped Features

### LinkedIn Scraper (T-04, T-05)
- `scrapers/linkedin.py` — full `LinkedInScraper` implementation using Apify actor `2rJKkhh7vjpX7pvjg`.
- Normalises all LinkedIn fields to `NormalizedJob`, including `salaryInfo → budget` and platform extras (`company_name`, `location`, `work_type`, `sector`, `applications_count`, `apply_type`, `posted_time`, `poster_name`, `company_url`).
- `configs/prompts/linkedin_context.json` — evaluation prompt context tailored for LinkedIn jobs: competition signal via `applications_count`, remote/hybrid weighting via `work_type`, salary from `salaryInfo`.
- `configs/platforms/linkedin.json` — actor config with field mappings and defaults.

### Multi-Platform Pipeline (T-06, T-07)
- `PipelineService.run_pipeline()` now accepts `platforms: list[str] | None`. Passing `None` runs all configured platforms (backwards-compatible).
- `POST /api/run` now accepts a JSON body `{ "platforms": ["upwork", "linkedin"] }` instead of a query parameter. Omit or pass `null` to run all platforms.
- Validation: unknown platform slugs → 422; platform without a saved config → 400; empty list → pipeline error.

### Platforms API (T-08)
- `GET /api/platforms` returns a registry-driven list of all known platforms with a `has_config` flag per authenticated user.
- Response shape: `[{ "slug": "upwork", "has_config": true }, { "slug": "linkedin", "has_config": false }]`.

### Version Endpoint & Footer (T-02, T-03)
- `GET /api/version` (no auth) returns `{ "version": "2.2.0" }` read from the `VERSION` file at startup. App fails fast if the file is missing.
- Frontend `version-footer.tsx` displays the version on all authenticated pages. Fetched once and cached indefinitely via `use-version.ts`.

### Platform Selection Dialog (T-09, T-10)
- "Run Pipeline" button now opens a shadcn Dialog listing all known platforms.
- Unconfigured platforms are disabled with a tooltip linking to `/search-config?platform=<slug>`.
- Selecting zero platforms disables the Confirm button. Confirming sends only the selected platforms to `POST /api/run`.

### LinkedIn Search Config Form (T-11)
- Search Config page is now tabbed (Upwork | LinkedIn), driven by `/api/platforms`.
- `linkedin-form.tsx` exposes: `keyword` (tag input), `location`, `distance`, `publishedAt` (24h/week/month), `jobType`, `experienceLevel`, `workType`, `salaryBase`, `maxItems` (≤1000), `saveOnlyUniqueItems`.
- Saved as a normal `search_configs` row with `platform = "linkedin"`.

### Real-Time Pipeline Status (T-12, T-13)
- `useRunStatus(runId)` polls every 2 s while a run is active, stops immediately on `completed` or `failed`, and invalidates results/dashboard queries on completion.
- Reloading the page during an active run restores the animated running state immediately by seeding from `recent_runs[0]`.

### UX Improvements (T-14, T-15)
- **Add-to-list dropdown** — "Create new list…" option at the bottom creates a list and adds the job in one flow, with toast feedback on error.
- **Profile "Clear all"** — destructive AlertDialog button resets all profile fields to empty and saves, with a toast on success.

### Bug Fixes (T-01)
- Session and CSRF cookies now set with `Path=/`, preventing auth state loss when navigating between routes.

## Migration Notes

### No database schema changes
All v2.2 features use the existing schema. LinkedIn jobs are stored in `job_results` with `platform = "linkedin"` — the existing `UNIQUE (user_id, platform, job_id)` constraint handles deduplication automatically.

### `POST /api/run` request body change
If you call this endpoint directly, update from the old query-parameter form:
```
# Old (removed)
POST /api/run?platform=upwork

# New
POST /api/run
Content-Type: application/json
{ "platforms": ["upwork"] }

# Run all configured platforms
POST /api/run
Content-Type: application/json
{}
```

### New required files
- `VERSION` — must exist at repo root with a semver string. App fails fast at startup if missing.
- `configs/platforms/linkedin.json` — required for the LinkedIn scraper to initialise.
- `configs/prompts/linkedin_context.json` — required for LinkedIn job evaluation.

### Environment variables
No new environment variables were added in v2.2. The existing `APIFY_API_TOKEN` is used for both Upwork and LinkedIn actors.
